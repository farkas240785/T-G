# Система авторизации и регистрации

Реализована полноценная система аутентификации для личного кабинета.

## 🔐 Компоненты системы

### 1. AuthContext (`src/context/AuthContext.tsx`)
Контекст React для управления состоянием авторизации:
- Хранение данных текущего пользователя
- Методы: `login()`, `register()`, `logout()`
- Сохранение сессии в localStorage
- Автоматическое восстановление сессии при перезагрузке

**Типы пользователей:**
- `customer` - Заказчик (снабжение/прораб)
- `architect` - ГИП / Архитектор-реставратор
- `technologist` - Технолог
- `manager` - Менеджер

### 2. Страница входа (`/login`)
**Функционал:**
- Форма входа по email и паролю
- Валидация данных
- Обработка ошибок (неверный email/пароль)
- Перенаправление на запрошенную страницу после входа
- Ссылка на регистрацию
- Демо-доступ для тестирования

**Демо-аккаунты:**
```
Архитектор: demo@tigelgorn.ru / demo123
Менеджер: manager@tigelgorn.ru / manager123
```

### 3. Страница регистрации (`/register`)
**Функционал:**
- Форма регистрации с полями:
  - Название организации
  - Роль (выпадающий список)
  - ФИО
  - Телефон (опционально)
  - Email
  - Пароль (минимум 6 символов)
  - Подтверждение пароля
- Валидация:
  - Совпадение паролей
  - Минимальная длина пароля
  - Проверка на существующий email
- Согласие на обработку персональных данных (ФЗ-152)
- Ссылка на пользовательское соглашение
- Информация о целевой аудитории

**Целевая аудитория:**
- Реставрационные СРО и организации
- Музеи и объекты культурного наследия
- Генподрядчики на объектах КГИОП
- Архитекторы-реставраторы

### 4. ProtectedRoute (`src/components/ProtectedRoute.tsx`)
Компонент для защиты маршрутов:
- Проверка авторизации
- Перенаправление на `/login` при отсутствии доступа
- Сохранение пути для возврата после входа

### 5. Обновлённый Header
- Отображение имени пользователя (для авторизованных)
- Кнопка "Выйти"
- Ссылка "Войти" (для неавторизованных)
- Мобильное меню с учетом авторизации

## 🛡️ Защищённые маршруты

Все маршруты личного кабинета защищены:
- `/dashboard` - главная ЛК
- `/dashboard/order/:id` - трекер заказа
- `/dashboard/configurator` - конфигуратор
- `/dashboard/object-folder` - папка объекта
- `/dashboard/finance` - финансы

При попытке доступа без авторизации → редирект на `/login` с сохранением пути.

## 📊 Mock-данные

В `AuthContext.tsx` реализована имитация базы данных:
```typescript
const MOCK_USERS = [
  {
    id: 'user-001',
    email: 'demo@tigelgorn.ru',
    password: 'demo123',
    name: 'Иванов Сергей Петрович',
    company: 'ООО "Реставрация-СПб"',
    role: 'architect',
    phone: '+7 (812) 555-12-34',
  },
  // ...
];
```

**Для продакшена необходимо:**
1. Заменить mock-данные на реальный бэкенд
2. Реализовать хеширование паролей (bcrypt)
3. Использовать JWT токены
4. Добавить refresh tokens
5. Реализовать восстановление пароля через email

## 🔒 Безопасность

**Текущая реализация (демо):**
- Пароли хранятся в открытом виде (только для демо!)
- Сессия в localStorage
- Нет защиты от CSRF/XSS

**Для продакшена необходимо:**
- Хеширование паролей на сервере
- JWT с коротким временем жизни
- Refresh tokens в httpOnly cookies
- Rate limiting для защиты от brute-force
- CAPTCHA при множественных неудачных попытках
- Двухфакторная аутентификация (2FA)
- HTTPS обязательно
- Валидация на сервере

- Мобильное меню с учётом авторизации

## 📝 Сценарии использования

### Сценарий 1: Новый пользователь
1. Переход на `/register`
2. Заполнение формы регистрации
3. Подтверждение согласия на обработку ПД
4. Автоматический вход после регистрации
5. Перенаправление в ЛК

### Сценарий 2: Существующий пользователь
1. Переход на `/login`
2. Ввод email и пароля
3. Успешный вход
4. Перенаправление в ЛК (или на запрошенную страницу)

### Сценарий 3: Попытка доступа к ЛК без авторизации
1. Переход на `/dashboard`
2. Редирект на `/login` с сохранением пути
3. Вход в систему
4. Автоматический возврат на `/dashboard`

### Сценарий 4: Выход из системы
1. Клик на "Выйти" в Header
2. Очистка сессии
3. Перенаправление на главную страницу
